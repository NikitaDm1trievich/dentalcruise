# Работы «до/после»

Лента «Галерея работ» (`/gallery/`) и страница каждой работы со слайдером
сравнения (`/gallery/<имя файла>/`, `src/pages/gallery/[slug].astro`). Один
JSON-файл на работу; имя файла — адрес страницы работы. Загрузчик берёт
только `*.json`, этот README игнорируется.

Работы добавляет владелец в редакторе: `/admin` → «Галерея работ (до и
после)» → «Создать». Редактор сам создаёт файл здесь (имя латиницей из типа
работы и времени: `veneers-20261001-143015.json`) и кладёт фото в
`src/assets/cases/`.

```json
{
  "title": "Имплантация и циркониевые мостовидные протезы",
  "category": "implants",
  "before": "/images/cases/implants-zirconia-bridges-01-before.jpg",
  "beforePosition": "",
  "after": "/images/cases/implants-zirconia-bridges-01-after.jpg",
  "afterPosition": "50% 100%",
  "beforeCaption": "Фото до лечения. …",
  "afterCaption": "Фото после протезирования. …",
  "note": "Строка для карточки в ленте и под заголовком работы",
  "description": "Первый абзац.\n\nВторой абзац.",
  "steps": ["Диагностика и план лечения", "Установка имплантов"],
  "seoDescription": "",
  "order": 20
}
```

- `category` — `veneers` / `crowns` / `implants` (выпадающий список «Тип
  работы» в редакторе). По нему работает фильтр и надпись над заголовком
  страницы работы; подписи — в `src/data/pages/gallery.json` (`filter`).
- Фото. Оригиналы лежат в `src/assets/cases/` — вне `public`, на хостинг они
  не попадают. В записи путь пишется как `/images/cases/<файл>` (так его
  показывает редактор), а сборка делает из файла копии со знаком клиники:
  кадр 4:3, ширина 1600 и 800 px, webp, без EXIF, логотип внизу по центру
  (`src/lib/case-photos.ts`, адрес `src/pages/images/cases/[name].webp.ts`).
- `beforePosition` / `afterPosition` — необязательно: какую часть снимка
  оставить в кадре 4:3, как `object-position` в CSS («50% 100%» — низ). Нужно,
  когда у «до» и «после» разные пропорции и зубы оказываются на разной
  высоте в слайдере.
- `photos` — необязательно: ещё снимки под слайдером (другой ракурс,
  вторая челюсть), список `{ "photo", "position", "zoom", "caption" }`.
  Кадр 4:3 и знак — как у «до/после»; снимок без файла пропускается, работа
  от этого с сайта не пропадает.
- `description` — абзацы через пустую строку; `steps` — «Что сделано»,
  необязательный список. Пустые блоки на странице не рисуются.
- `seoDescription` — пусто: описание для поиска собирается из названия,
  `note` и первого абзаца.
- `order` — порядок в ленте и соседи «предыдущая/следующая».
- Работа без одного из фото (или с пропавшим файлом) на сайт не выходит —
  ни в ленту, ни отдельной страницей (`src/lib/cases.ts`).
- Пока нет ни одной работы с обоими фото, страница показывает текст «идёт
  съёмка» (`empty` в `gallery.json`), закрыта от поисковиков (noindex) и не
  попадает в карту сайта (`astro.config.mjs`). Первая работа открывает её.
