# Дентал Круиз — сайт клиники

Статический сайт на Astro. Дизайн утверждён в Claude Design; макет и дизайн-система
лежат рядом в репозитории как референс (см. [Что где лежит](#что-где-лежит)).

## Быстрый старт

```bash
npm install
npm run dev
```

Сайт поднимется на http://localhost:4321.

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер с горячей перезагрузкой |
| `npm run build` | Статическая сборка в `dist/` |
| `npm run preview` | Локальный просмотр собранного `dist/` |
| `npm run check` | Проверка типов и шаблонов Astro |

Нужен Node 24 (версия зафиксирована в `.nvmrc`).

## Как поменять контент, не трогая вёрстку

Весь изменяемый контент — JSON-файлы в `src/content/`. Добавить врача или позицию
прайса = добавить запись в файл, пересобрать, готово.

| Папка | Что там | Формат |
|---|---|---|
| `src/content/doctors/` | Врачи и техники | один файл на человека |
| `src/content/services/` | Топ-услуги на главной | один файл на услугу |
| `src/content/service-categories/categories.json` | Направления: каталог на главной, меню «Услуги», якоря прайса | один массив |
| `src/content/service-pages/` | Страницы услуг `/uslugi/<файл>` | один файл на услугу, шаблон `_template.json` |
| `src/content/price-list/` | Полный прайс | один файл на категорию |
| `src/content/cases/` | Кейсы «до/после» | один файл на кейс, см. README внутри |
| `src/content/faq/faq.json` | Вопросы и ответы | один массив |
| `src/content/promos/promos.json` | Плашка акций | один массив |
| `src/content/brands/brands.json` | Бегущая строка поставщиков | один массив |
| `src/content/trust/trust.json` | Полоса доверия перед подвалом | один массив |
| `src/content/comparison/comparison.json` | «Мы vs обычная клиника» | один массив |

Схемы полей описаны в [`src/content.config.ts`](src/content.config.ts) — сборка
падает с понятной ошибкой, если в JSON опечатка или не хватает поля.

Порядок вывода задаёт поле `order` (меньше — выше). На главную попадают только
записи с `"featured": true` — так список врачей на отдельной странице может быть
длиннее, чем тизер на главной.

Строка прайса становится ссылкой на страницу услуги, если совпадают направление
(`category`) и название — `title` страницы или, когда в прайсе позиция названа
короче, `matchTitle`. Если одно и то же название есть в нескольких группах раздела
(«На импланте, винтовая фиксация» у циркониевых, металлокерамических, E.max и
временных коронок), у страницы указывается ещё и `matchGroup` — название группы
прайса. Без него все такие строки вели бы на одну страницу, а остальные
оставались без единой входящей ссылки.

Фотографии лежат в `public/images/` (`lab`, `team`, `clinic`, `services`).
Исходники остаются в `assets/` и в сборку не идут: в `public/` кладутся сжатые
веб-версии шириной 1200 px. Данные графика цен — в `src/data/price-chart.ts`.

**Контакты, адрес, часы работы, телефон** — не в JSON, а в
[`src/data/site.ts`](src/data/site.ts). Оттуда их берут шапка, подвал, бургер-меню,
карточка места и микроразметка JSON-LD сразу — правится в одном месте.

## Форма записи

Форма отправляет заявку POST-запросом на Cloudflare Worker, тот пересылает её в
Telegram-бота. Токен бота живёт в секретах Worker'а и в браузер не попадает.

Адрес эндпоинта задаётся переменной `PUBLIC_BOOKING_ENDPOINT` (см. `.env.example`).
Пока переменная не задана, форма не притворяется рабочей: она показывает сообщение
и предлагает позвонить.

Настройка Worker'а — [`worker/README.md`](worker/README.md).

## Публикация

### Сейчас: GitHub Pages

Пуш в `main` запускает [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):
проверка (`npm run check`), сборка и публикация в Pages. Сборка на github.io —
тестовая: страницы уходят с `noindex`, а `robots.txt` закрывает обход, чтобы
после переезда в поиске не оказалось дубля сайта (подробнее — в
[`docs/seo.md`](docs/seo.md)).

Разово нужно включить в настройках репозитория:

1. **Settings → Pages → Source** переключить на **GitHub Actions**
   (сейчас там отдаётся файл `index.html` из корня — офлайн-экспорт макета).
2. **Settings → Secrets and variables → Actions → Variables** добавить
   `PUBLIC_BOOKING_ENDPOINT` с адресом Worker'а.

### Потом: хостинг клиники

Домен и базовый путь читаются из окружения, в коде их нет:

```bash
SITE=https://dentalcruise.ru BASE=/ npm run build
```

В workflow они заданы в блоке `env:` в начале `deploy.yml`. Содержимое `dist/`
кладётся в корень сайта. Ничего в коде менять не нужно — это и есть переезд
с Битрикса; сборка на боевом домене сама открывается для индексации.

## Что где лежит

```
src/
  components/
    core/       кнопки, бейджи, иконки, заголовки секций, обёртка появления
    content/    блоки главной: акции, карусель, флип-карточки, FAQ, отзывы…
    forms/      модалка и форма записи
    layout/     шапка, бургер-меню, подвал
    media/      hero с видео, волны, фото-заглушка со skeleton
    seo/        мета-теги, Open Graph, JSON-LD
  content/      JSON-контент (см. выше)
  data/site.ts  контакты клиники — единственный источник правды
  layouts/      BaseLayout (общий каркас), StubLayout (страницы-заготовки)
  lib/          ссылки с учётом базового пути (asset), сборщики SEO (seo),
                появление при скролле, логика оверлеев
  pages/        маршруты
  styles/       глобальные стили + токены дизайн-системы
public/         логотип, favicon, иконка для iPhone, обложка для соцсетей, hero-видео
worker/         Cloudflare Worker для формы записи
```

Референс дизайна (не участвует в сборке): `Дентал Круиз - лендинг.dc.html`,
`DoctorFlipCard.dc.html`, `LicenseDrawer.dc.html`, `_ds/`, `standalone-src.html`.

## Технические решения

**Ссылки — только через [`src/lib/asset.ts`](src/lib/asset.ts).** Сайт собирается
и в корень домена, и в подпапку GitHub Pages (`BASE=/dentalcruise/`), поэтому путь
в шаблоне руками не пишется. На страницу — `pageHref('pricelist#protezirovanie')`
→ `/dentalcruise/pricelist/#protezirovanie`: всегда со слешем, потому что так
страницы отдаёт сервер, так они записаны в canonical и в карте сайта, а адрес без
слеша — лишний редирект. На файл (картинка, видео, svg) — `withBase('images/…')`.
Абсолютные адреса для JSON-LD и фидов — `absolute()` из
[`src/lib/seo.ts`](src/lib/seo.ts).

**Токены дизайн-системы — источник правды по стилям.** Файлы в
`src/styles/tokens/` скопированы из `_ds/` без изменений: там уже выверены
контраст (WCAG AA), типографская шкала и тайминги анимаций. Tailwind подключён и
пробрасывает эти токены в утилиты через `@theme inline` в
[`src/styles/global.css`](src/styles/global.css) — значения нигде не дублируются.

**Иконки инлайнятся на сборке.** В макете Lucide грузился UMD-скриптом с CDN.
Здесь пакет `lucide` читается в build-time, и в HTML попадает готовый SVG: без
запроса к CDN, без мигания иконок, без JS в браузере.

**График цен — свой SVG, а не библиотека.** Пробовали bklit ui (в npm его нет:
это registry в стиле shadcn на React + visx) и tremor. Tremor v3 рассчитан на
Tailwind v3 со своим preset — на Tailwind v4 его стили не применяются, а связка
`@astrojs/react` с Rolldown-сборщиком Astro 5.15 ломала и dev-сервер
(`Missing field moduleType`), и сборку (`React is not defined`). Ради одного
блока это ~180 КБ клиентского JS и нерабочий тулчейн, поэтому
[PriceChart.astro](src/components/content/PriceChart.astro) считает геометрию на
сборке и отдаёт готовый SVG: те же градиентные области и подсказки, единицы
килобайт. Шкала начинается с нуля — у диаграмм с областями усечённая база
зрительно раздувает разницу.

**Ноль JS-фреймворков в браузере.** Интерактив (меню, модалка, аккордеон,
флип-карточки, карусель) — обычный DOM в `<script>` компонентов. Anime.js
используется для появления секций при скролле и кроссфейда карусели; переходы,
для которых в токенах уже заданы точные CSS-тайминги (морф бургера, поворот
шеврона, раскрытие аккордеона), оставлены на CSS — это и легче, и ближе к макету.

**Появление секций отказоустойчиво.** Блок с `opacity: 0`, который проявляет JS, —
риск: `requestAnimationFrame` замирает на фоновой вкладке, и посетитель может
увидеть пустую страницу. Поэтому у каждого появления три пути к финальному
состоянию: штатное завершение анимации, сторожевой таймер и уход вкладки в фон.
Без JS (`.no-js`) весь контент виден сразу.

**Тяжёлое грузится лениво.** Виджеты Яндекс Карт монтируются, только когда
доезжают до экрана. Hero-видео не грузится вовсе при `Save-Data`, медленном
соединении или `prefers-reduced-motion` — остаётся poster-кадр.
