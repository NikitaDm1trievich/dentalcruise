# Редактор сайта

Правки контента без программиста. Открывается по адресу `/admin/` на живом
сайте, сохраняет изменения коммитом в GitHub, после чего сайт пересобирается
автоматически — обычно за 1–2 минуты.

Технически это [Sveltia CMS](https://github.com/sveltia/sveltia-cms) поверх
JSON-файлов в `src/content/` и `src/data/`. Версия закреплена в
`index.html`; обновлять её нужно осознанно.

## Как войти владельцу

Инфраструктуру поднимать не нужно — вход по личному токену GitHub.

1. Владельцу нужен аккаунт на github.com, добавленный в репозиторий с правом
   записи: Settings → Collaborators → Add people.
2. Создать токен: github.com → Settings → Developer settings →
   Personal access tokens → **Fine-grained tokens** → Generate new token.
   - Repository access: **Only select repositories** → `dentalcruise`
   - Permissions → Repository permissions → **Contents: Read and write**
   - Expiration: на своё усмотрение; после истечения токен нужно выпустить заново
3. Открыть `/admin/`, нажать «Войти с помощью токена доступа», вставить токен.

Токен хранится только в браузере владельца и никуда с сайта не уходит.
Он даёт доступ на запись в этот один репозиторий — обращаться с ним как с
паролем, не пересылать в мессенджерах.

## Локальные правки (для разработчика)

Запустить `npm run dev` и открыть <http://localhost:4321/admin/index.html>.

Важно: локально нужен именно `/admin/index.html` — dev-сервер Astro не
подставляет `index.html` для папок из `public/`. На живом сайте `/admin/`
работает как обычно.

Дальше «Работать с локальным репозиторием» → выбрать корневую папку проекта.
Правки идут прямо в файлы на диске, GitHub и токен не нужны. Работает в
Chrome и Edge (нужен File System Access API).

## Если понадобится вход через GitHub вместо токена

Более удобный для владельца вариант — кнопка «Войти через GitHub» без ручного
токена. Для неё нужен OAuth-прокси:

1. Развернуть [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth)
   как Cloudflare Worker (у клиники уже есть аккаунт Cloudflare — там же
   живёт воркер формы записи).
2. Создать GitHub OAuth App, callback указать на адрес воркера.
3. Прописать в воркер секреты `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET`.
4. Добавить в `config.yml` в блок `backend` строку:
   `base_url: https://<ваш-воркер>.workers.dev`

## Как устроен редактор

Слева разделы:

- «Главная страница» и «Страницы сайта» — тексты страниц. Внутри «Главной»
  пункты пронумерованы так же, как блоки на странице сверху вниз: «Тексты
  блоков 1–12» — заголовки, тексты и кнопки всех блоков, а «3. Акции —
  карточки», «4. Услуги — разделы и цены» и т.д. — списки карточек этих
  блоков. В «Страницах сайта» — по записи на страницу («О клинике»,
  «Контакты», «Прайс-лист — тексты страницы»…) и общие тексты страниц врача
  и услуги (заголовки блоков, кнопки).
- «Прайс-лист», «Страницы услуг», «Врачи» — данные: цены, услуги, врачи.
- «Шапка, подвал и контакты» — то, что стоит на всех страницах: телефон,
  адрес, режим работы, ссылки (один источник для шапки, подвала, «Контактов»,
  формы и разметки для поисковиков), меню, нижняя панель на телефоне,
  карточка с адресом, окно лицензии, форма записи.
- «Цвета сайта» и «Поиск и счётчики» — настройки.

У каждой страницы есть группа «Для поисковиков» — заголовок и описание в
выдаче (до ~60 и ~160 знаков).

Справа — живой предпросмотр страницы. Если навести мышь на блок, он
обводится рамкой с подписью; нажатие открывает слева нужное поле или группу
полей. Если блок хранится в другой записи (например, карточки акций на
главной или телефон в шапке), редактор сам перейдёт в неё. Замком помечено
только то, чего в редакторе нет: виджеты Яндекс Карт, логотип, фото клиники.
Кнопка «Выбор блоков» над предпросмотром выключает этот режим — тогда
страницу можно листать и нажимать как обычно.

Тексты, в которые сайт сам вписывает данные, содержат метки в фигурных
скобках: `{позиций}` в тексте прайса, `{услуга}` в заголовке вопросов,
`{месяце}` и `{сумма}` под графиком цен. Метки нельзя переводить и удалять.

Цвета сайта правятся в разделе «Цвета сайта»: справа сразу видно, как цвет
ложится на страницу.

## Что важно знать про контент

**Поля «Служебное: …».** У записей в списках (акции, вопросы, поставщики и
т.д.) есть поле «Служебное: ID». По нему сайт отличает записи друг от друга.
Оно должно быть уникальным и латиницей. У существующих записей менять его
нельзя — сломаются ссылки и якоря. То же касается остальных полей с
подписью «Служебное».

**Иконки.** Выбираются только из выпадающего списка. Произвольное имя уронит
сборку сайта — поэтому поле и сделано списком, а не текстом.

**Разделы прайса.** Значение «Служебное: адрес раздела в прайсе» у раздела в
«Главная страница» → «4. Услуги — разделы и цены» должно совпадать со
«Служебное: адрес раздела» у файла в «Прайс-листе» — иначе ссылка из
каталога никуда не приведёт.

**Лицензия и реквизиты.** Номер, дата, лицензирующий орган, ссылка на реестр,
выписка (PDF) с миниатюрой для подвала и сканы бланка — «Шапка, подвал и
контакты» → «Контакты и реквизиты клиники», группа «Лицензия»; ООО, ИНН и ОГРН —
там же, группа «Реквизиты юрлица». Всё взято из выписки из реестра лицензий
Росздравнадзора (`public/docs/vypiska-iz-reestra-licenziy.pdf`). Сканы
листаются в окне лицензии в порядке списка, подпись скана видна под ним и
читается незрячим вместо картинки. Новую выписку загрузили — замените и
миниатюру: это картинка первой страницы PDF.

**Если сайт не обновился** через пару минут после сохранения — смотреть вкладку
Actions в репозитории: там видно, упала сборка или ещё идёт.

**«Редактор при сохранении стёр заполненные поля».** Если на шаге «Проверка,
что редактор не стёр поля» публикация остановилась, значит, запись сохранили
из вкладки редактора, открытой до его обновления, и из файла пропало
заполненное поле. Сайт при этом остаётся прежним. В логе указаны коммит, файл
и поле с прежним значением. Что сделать: перезагрузить все вкладки редактора,
открыть эту запись, заново заполнить поле и сохранить — следующая публикация
пройдёт. Очищать поля можно спокойно: пустое поле редактор сохраняет пустым, а
не удаляет, и проверка на это не срабатывает. Проверка смотрит только коммиты
редактора («Обновить «…»: …»), коммиты разработчика она пропускает.

## Плашка «Редактор обновился»

Вкладка редактора знает поля из `config.yml` на момент, когда её открыли. Если
потом в редактор добавили поле, а владелец сохраняет запись во вкладке,
открытой раньше, — редактор молча выбрасывает незнакомое ему поле из файла.
Так 27.09 пропала «Крупная надпись под услугами» у двух врачей.

Поэтому сборка (`astro.config.mjs`, хук `dc-admin-cache-bust`) считает версию
редактора — отпечаток `config.yml` и `preview.js` — и кладёт её в
`admin/index.html` (`<meta name="dc-admin-version">`) и в файл
`admin/version.txt`. `preview.js` раз в две минуты и при возврате на вкладку
сверяет их. Сменилась версия — справа внизу появляется плашка «Редактор
обновился. Сохраните текущую запись и перезагрузите страницу…» с кнопками
«Перезагрузить» и «Позже» (скрывает до следующей проверки).

Что делать владельцу, увидев плашку: сохранить открытую запись (её поля
редактору известны) и нажать «Перезагрузить». Работать дальше в старой
вкладке нельзя — следующее сохранение может стереть новые поля.

Там же к адресам `config.yml` и `preview.js` дописывается `?v=<отпечаток>`,
чтобы браузер не взял старую копию из кэша. Локально (`npm run dev`) версии
нет, и проверка выключена.
