# SEO Dental Cruise: устройство и проверка

Актуализировано 1 ноября 2026 года. Документ описывает текущую реализацию
репозитория; наличие правок в рабочей копии ещё не означает публикацию.
Сравнение рынка и географии — [в отчёте](local-seo-competitor-audit-2026-11-01.md),
цены конкурентов — [в приложении](competitor-prices-2026-11-01.md).

## Домен и индексация

Боевой сайт — `https://dentalcruise.ru/`. GitHub Pages остаётся тестовой копией
с `noindex, nofollow` и `Disallow: /`. Не менять домен workflow на боевой ради
индексации: production публикуется отдельно через `scripts/deploy-prod.sh`.

`SITE` и `BASE` определяют canonical, ссылки, фиды и sitemap. Страницы имеют
завершающий слеш; файлы — адрес без добавленного слеша. Ссылки на страницы
строятся через `pageHref()`, на файлы — через `withBase()`. Старые адреса после
переезда должны перенаправлять на соответствующие действующие страницы.
Проверка 1 ноября: www и HTTP ведут на HTTPS без www, `/about/doctors/` — на
`/doctors/`; отсутствующая страница возвращает HTTP 404.

- `/robots.txt` собирается из `src/pages/robots.txt.ts`. На сервере есть особое
  правило nginx; deploy кладёт также идентичный `robots-site.txt`.
- `/sitemap-index.xml` и `/sitemap-0.xml` создаёт `@astrojs/sitemap`. Служебные
  страницы и пустая галерея исключаются. `priority`/`changefreq` не следует
  считать способом повышения позиции или гарантией частого обхода Google.
- Галерея без опубликованных пар фото закрывается `noindex`; при наличии
  работ страницы открываются. Это не повод открывать тестовую сборку.

## Источники данных и редактирование

| Что | Файл / место в CMS |
|---|---|
| Название, адрес, телефон, график, метро и профили | `src/data/clinic.json`, «Шапка, подвал и контакты» |
| Главная, её title и description | `src/data/home.json` |
| Контакты, о клинике, прайс, команда | `src/data/pages/*.json`, «Страницы сайта» |
| Отдельные услуги, цены и включения | `src/content/service-pages/*.json` |
| Полный прайс | `src/content/price-list/*.json` |
| Врачи, их услуги и SEO | `src/content/doctors/*.json` |
| Работы и их SEO | `src/content/cases/*.json` |
| Вопросы главной | `src/content/faq/faq.json` |
| Подтверждения, Метрика, район | `src/data/seo.json`, «Поисковая оптимизация» |

У услуг и врачей title/description создаются автоматически при пустых ручных
полях. У восьми важных услуг заданы отдельные метатексты. Не копировать в ручное
описание акционную цену без необходимости: её изменение в прайсе само по себе
не обновляет вручную написанный SEO-текст.

У работы `seoTitle` позволяет различить одинаково названные случаи в поиске,
сохраняя видимый заголовок. Новые поля есть в схеме Astro и конфигурации CMS.
После обновления конфигурации перезагрузить уже открытую админку.

Обе станции берутся из `metroStations`. `clinic.metroLabel` собирает их для
автоматических описаний, `clinic.areaServed` — город, район из `seo.region.district`
и станции для разметки. `seo.region.landmarks` — заметка редактора, самостоятельно
на страницы не выводится. Список ориентиров в скрытом поле не заменяет полезный
видимый текст и реальные маршруты.

## География существующих страниц

Основное ядро: метро Полежаевская и Хорошёвская, Хорошёвский район,
4-я Магистральная, 5-я Магистральная и ближайшая часть Хорошёвского шоссе.
В существующих FAQ и контактах описан приезд из соседних зон: Ходынки, Беговой,
с улиц Куусинена и Зорге. Это одна клиника по одному адресу, не сеть филиалов.

Дизайн, маршруты URL и порядок блоков сохранены. В блоке лаборатории на услуге
доступны контакты, подходящие работы клиники и ссылки на врачей, которые уже
указали эту услугу в своих карточках. Хирург не назначается по предположению.

Новые страницы улиц создавать только при самостоятельной пользе: проверенный
маршрут, ориентиры, доступность и содержательные сведения. Массовые копии с
заменой станции или района могут быть дорвеями.
[Правила Google](https://developers.google.com/search/docs/essentials/spam-policies#doorway-abuse).

## Микроразметка и значки

`src/components/seo/Seo.astro` формирует `Dentist` и `WebSite` на главной,
хлебные крошки и FAQ по фактически показанным вопросам. Внутренние услуги
описываются как `Service`, прайс — `OfferCatalog`; исполнители ссылаются на общий
идентификатор клиники. Техник в персональной разметке — `Person`.

Цены «от» передаются через `PriceSpecification.minPrice`, а не как фиксированная
сумма. Цены этапов All-on-4/6 не выдаются за полный комплект с протезом.
Разметка `Service` не гарантирует показ цены, а `FAQPage` — расширенный сниппет.
Рейтинг самой клиники в `aggregateRating` не размечается: Google не предоставляет
self-serving review stars для LocalBusiness, включая встроенные сторонние отзывы.
[Правила Google](https://developers.google.com/search/docs/appearance/structured-data/review-snippet#self-serving-reviews).

`sameAs` содержит проверенные ссылки на ту же организацию. Google Maps добавлен
по существующей карточке; 2ГИС/ПроДокторов/Zoon остаются незаполненными до проверки
реальных профилей. Микроразметка не переносит автоматически рейтинг и не гарантирует
позицию на Картах. Гео-метатеги тоже не являются главным инструментом продвижения.
[Разметка LocalBusiness](https://developers.google.com/search/docs/appearance/structured-data/local-business).

Значки: `/images/favicon.ico` (16/32/48), `/favicon-96x96.png`,
`/apple-touch-icon.png` (180). Исходный SVG сохранён. ICO лежит в `images/`, потому
что точный `/favicon.ico` перехватывает старое правило nginx. Google обновляет
значок после повторного обхода; конкретный срок и показ не гарантированы.

## Кабинеты, карты и аналитика

Google Search Console подтверждён 1 ноября; sitemap отправлен, индексация главной
запрошена. Токен в `seo.verification.google` сохранять. Это отдельный доступ от
Google Business Profile. Яндекс-токен присутствует в данных; текущий доступ к
кабинету Вебмастера проверяется отдельно.

Карточка Google существует. При проверке 1 ноября показывала 4,9 и 7 отзывов.
В ней замечены лишнее «я» в адресе и открытие в 09:00 вместо 10:00. Владелец
подтвердил актуальность графика сайта: пн–сб 10:00–22:00, воскресенье выходной.
Для исправления проверить доступ к существующей карточке, не создавать дубль.
Название, адрес и телефон должны описывать одну организацию; варианты записи
«5с1» и «5, строение 1» сами по себе не означают разные компании.

Заполнять профиль реальными категориями, услугами, графиком и фотографиями входа.
У настоящих пациентов можно просить отзыв через ссылку/QR без вознаграждения и
отбора только довольных. Результаты карт зависят от соответствия запросу,
расстояния и известности; доступ к кабинету и число отзывов не гарантируют топ-3.
[Локальный поиск Google](https://support.google.com/business/answer/7091?hl=ru),
[отзывы](https://support.google.com/business/answer/3474122?hl=ru).

Метрика на production подключается только после согласия посетителя. Основные
события: `booking_sent`, `phone_click`; реализация — `src/lib/analytics.ts`.
На staging номер счётчика не передаётся. Считать небрендовые показы/клики,
посадочные страницы и реальные обращения, а не только место по одному запросу.

## Фиды и IndexNow

- `/feeds/doctors.xml` — фид специалистов для подключения в Яндекс Вебмастере.
- `/feeds/services.xml` — услуги/цены. Приём и фактическую доступность импорта
  нужно проверить в кабинете целевого сервиса; наличие XML не доказывает импорт.
- Ключ IndexNow сейчас пуст. `scripts/indexnow.mjs` может уведомлять
  поддерживающие протокол системы после настройки; Google IndexNow не использует.
  Текущий production-deploy сам этот скрипт не запускает. Уведомление не
  гарантирует индексацию и не заменяет sitemap/Search Console.

## Проверки перед публикацией

```bash
npm run check
npm run build
npm run check:seo
```

Последняя команда требует Python 3 без сторонних пакетов. Она проверяет собранные
HTML: метатеги, один H1, canonical, robots, валидный JSON-LD, уникальные метатексты,
внутренние ссылки/якоря, локальные ресурсы, alt, входящие ссылки, sitemap и смысл
цены услуги относительно контента. Production-deploy вызывает её до загрузки.

Проверка тестовой сборки с префиксом:

```bash
SITE=https://nikitadm1trievich.github.io BASE=/dentalcruise/ npm run build
npm run check:seo -- --site https://nikitadm1trievich.github.io/dentalcruise/ --staging
```

В workflow эта проверка стоит между сборкой и публикацией артефакта. Проверять
настоящий экран при изменении текстов и ссылок, особенно ширины 320/375 px.
Не отправлять реальные заявки при проверке без отдельного поручения.

## Следующие этапы

Проверить доступ к профилям и исправить подтверждённые расхождения. Собрать
реальные маршруты с выходами метро и фото входа. По мере накопления статистики
выбирать дополнительные улицы и услуги по спросу и обращениям. Медицинские
статьи выпускать с проверкой врачом; ежедневные общие тексты не заменяют эту работу.
Сроки и позиции SEO не гарантируются.
