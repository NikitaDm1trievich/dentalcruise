# Обработчик формы записи (Yandex Cloud)

Принимает заявку с сайта и отправляет её письмом на `info@dentalcruise.ru`.
Больше нигде заявку не хранит: письмо в ящике Яндекс 360 и есть хранилище.

Зачем отдельный сервис: сайт статический, отправить письмо сам он не может, а
доступ к почтовому сервису нельзя класть в код страницы — любой посетитель
прочитал бы его. Браузер обращается только к этому эндпоинту.

## Почему Yandex Cloud

Клиника — медицинская организация, а имя и телефон пациента — персональные
данные. По ч. 5 ст. 18 152-ФЗ их первая запись должна происходить в базах на
территории России, поэтому весь путь заявки проходит внутри РФ:

```
браузер ──► API Gateway ──► Cloud Functions ──► Cloud Postbox ──► ящик Яндекс 360
            (Yandex Cloud, регион ru-central1, Россия)          info@dentalcruise.ru
```

Раньше здесь был Cloudflare Worker с пересылкой в Telegram — оба сервиса
зарубежные, и это была бы трансграничная передача. Его убрали до запуска.

DNS домена остаётся на Cloudflare — это только адресная книга, заявки через
Cloudflare не идут: форма шлёт их прямо на адрес вида `*.apigw.yandexcloud.net`.
Если когда-нибудь понадобится свой адрес вроде `booking.dentalcruise.ru`, запись
в Cloudflare должна быть «DNS only» (серое облако), иначе трафик пойдёт через
серверы Cloudflare.

## Что уже сделано в коде

- CORS: читать ответ браузер позволит только доменам из `ALLOWED_ORIGINS`
- ограничение частоты: 5 заявок за 60 секунд с одного IP (как именно — ниже)
- ловушка для ботов: скрытое поле `website`, заполнено — заявка молча отбрасывается
- проверка полей и обязательное согласие на обработку данных
- телефон приводится к E.164 (`+79255777677`); не российский или неполный номер — 400
- в письмо попадают только имя, телефон, комментарий, страница-источник и
  реферер; IP посетителя не уходит никуда — он нужен лишь ограничителю частоты
- в логи функции данные заявки не пишутся, только причина сбоя отправки
- ключей нет ни в коде, ни в настройках: функция отправляет письма от имени
  своего сервисного аккаунта, токен ей выдаёт сама платформа

Весь код — один файл [`index.js`](index.js) без зависимостей; его можно
вставить в редактор консоли Yandex Cloud как есть, без сборки.

## Формат заявки

`POST /booking`, тело — JSON:

| Поле | Что это |
|---|---|
| `name` | имя, 2–80 символов |
| `contact` | телефон; сайт шлёт E.164 (`+79255777677`), но функция примет и `8 (925) 577-76-77`, и `9255777677` |
| `comment` | необязательно, до 600 символов (на форме поле «Комментарий») |
| `consent` | согласие на обработку данных: `"on"`, `"true"` или `true` |
| `page` | необязательно: адрес страницы, с которой ушла заявка, вместе с utm-метками (до 300 символов) |
| `referrer` | необязательно: откуда пришёл посетитель, `document.referrer` (до 300 символов) |
| `website` | ловушка для ботов — должно быть пустым |

Ответ — `{ "ok": true }`. При ошибке — `{ "ok": false, "error": "текст для пользователя" }`
со статусом 400 (поля), 429 (лимит) или 502 (почта не приняла письмо); текст
`error` форма показывает как есть.

Письмо приходит с темой «Заявка с сайта: Анна» и таким текстом:

```
Новая заявка с сайта

Имя: Анна
Телефон: +79255777677
Комментарий: Болит зуб
Страница: https://dentalcruise.ru/prices/?utm_source=yandex
Переход с: https://ya.ru/

11.10.2026, 12:30 МСК
```

Пустые необязательные поля в письмо не выводятся.

## Ограничение частоты: как оно работает и где его предел

У Cloud Functions нет общей памяти между экземплярами функции, поэтому лимит
«5 заявок в минуту с IP» считается в памяти каждого экземпляра отдельно.
Чтобы экземпляров было мало, на шаге 5 функции ставится ограничение
«не больше одного экземпляра на зону доступности». Зон в регионе несколько,
вызовы распределяются по ним случайно — значит, с одного IP пройдёт
не больше 5 × число зон заявок в минуту, а после простоя экземпляр может
пересоздаться и счётчик обнулится.

Для формы записи клиники этого достаточно: задача — не дать боту завалить
ящик сотнями писем, а не посчитать каждую заявку. Дополнительные рубежи:

- ограничение одновременных вызовов функции (тоже шаг 5): сверх него платформа
  сама отвечает 429, функция даже не запускается — расход не растёт;
- квоты Postbox на отправку.

Почему не другие варианты:

- лимит в самом API Gateway (`x-yc-apigateway-rate-limit`) Yandex Cloud
  объявил устаревшим и больше не поддерживает, к тому же он был общим на всех,
  а не на IP;
- счётчики в YDB или Object Storage дали бы точный общий лимит, но это ещё одна
  база с IP-адресами посетителей, лишний код и зависимость;
- если спам всё же пойдёт, следующий шаг — подключить к шлюзу
  [Smart Web Security](https://yandex.cloud/ru/docs/smartwebsecurity/) с
  ограничителем запросов ARL (платно, настраивается в консоли без правки кода) —
  именно его Yandex Cloud предлагает взамен устаревшего лимита шлюза.

## Сколько это стоит

При потоке заявок клиники — ноль рублей в месяц: всё укладывается в бесплатные
объёмы. Цены на октябрь 2026, в рублях с НДС:

| Сервис | Бесплатно каждый месяц | Дальше |
|---|---|---|
| [Cloud Functions](https://yandex.cloud/ru/docs/functions/pricing) | 1 млн вызовов и 10 ГБ×час | 18,97 ₽ за млн вызовов, 6,48 ₽ за ГБ×час |
| [API Gateway](https://yandex.cloud/ru/docs/api-gateway/pricing) | 100 000 запросов | 142,3 ₽ за млн запросов |
| [Cloud Postbox](https://yandex.cloud/ru/docs/postbox/pricing) | 2 000 писем | около 80 ₽ за 1 000 писем |
| [Логи функции](https://yandex.cloud/ru/docs/logging/pricing) | есть небольшой бесплатный объём | функция пишет в лог только строки об ошибках, объём ничтожный |

Одна заявка — это два запроса к шлюзу (проверка CORS и сама заявка), два
вызова функции и одно письмо. Даже 1 000 заявок в месяц далеко в бесплатной
зоне. Платёжный аккаунт при этом всё равно нужен и должен быть активным —
без него Postbox не работает.

## Настройка

Понадобится: аккаунт на Яндексе, с которого клиника будет управлять облаком
(лучше служебный, а не личный), доступ к панели Cloudflare, где лежит DNS
`dentalcruise.ru`, и доступ к ящику `info@dentalcruise.ru`.

Всё делается в браузере, в [консоли Yandex Cloud](https://console.yandex.cloud).
Регион везде один — `ru-central1`, его менять не нужно.

### 1. Облако, платёжный аккаунт и каталог

1. Открыть [console.yandex.cloud](https://console.yandex.cloud), войти через
   аккаунт Яндекса. При первом входе консоль создаст **облако**.
2. Создать **платёжный аккаунт**: Yandex Cloud предложит это сам
   (раздел [Billing](https://billing.yandex.cloud)). Для клиники выбирайте
   юридическое лицо или ИП — закрывающие документы будут на организацию.
   Статус аккаунта должен стать `ACTIVE` (или `TRIAL_ACTIVE` на пробном периоде).
3. В облаке создать **каталог** `dentalcruise` (кнопка «Создать каталог»). Всё
   дальнейшее создаётся внутри него — Postbox требует, чтобы адрес отправителя и
   сервисный аккаунт были в одном каталоге.

### 2. Сервисный аккаунт

Это «робот», от имени которого функция отправляет письма, а шлюз вызывает функцию.

1. Каталог `dentalcruise` → **Identity and Access Management** → **Сервисные
   аккаунты** → **Создать сервисный аккаунт**.
2. Имя: `dentalcruise-booking`.
3. Роли в каталоге — добавить две:
   - `postbox.sender` — отправка писем;
   - `functions.functionInvoker` — вызов функции через шлюз.
4. Создать. Ключи для него создавать **не нужно**.

### 3. Postbox: подтвердить домен dentalcruise.ru

Почтовые сервисы принимают письма только от подтверждённых доменов, иначе
заявки уйдут в спам или не дойдут вовсе.

1. Каталог `dentalcruise` → **Cloud Postbox** → **Создать адрес**.
2. Домен: `dentalcruise.ru`. Блок **DKIM** — вариант **Простая**. Логирование —
   по желанию (можно не включать). Создать.
3. На странице адреса появятся **две CNAME-записи**. Их нужно добавить в DNS
   домена, а DNS у `dentalcruise.ru` — на Cloudflare:
   1. [dash.cloudflare.com](https://dash.cloudflare.com) → домен
      `dentalcruise.ru` → **DNS** → **Records** → **Add record**.
   2. Type: `CNAME`. Name: имя из Postbox (Cloudflare сам допишет
      `.dentalcruise.ru`, если вставить имя целиком — тоже поймёт). Target:
      значение из Postbox.
   3. **Proxy status: DNS only** (серое облако). Это обязательно: с оранжевым
      облаком проверка DKIM не пройдёт.
   4. Сохранить и повторить для второй записи.
4. **SPF** — в тех же записях Cloudflare найти запись `TXT` на корне домена
   (Name `dentalcruise.ru` или `@`), которая начинается с `v=spf1`. Её создавали
   для почты Яндекс 360. Вторую такую запись создавать нельзя — нужно
   изменить существующую:
   - если там `v=spf1 redirect=_spf.yandex.net`, заменить на
     `v=spf1 include:_spf.yandex.net include:spf.postbox.yandexcloud.net ~all`;
   - если там что-то другое — добавить `include:spf.postbox.yandexcloud.net`
     перед `~all` или `-all`.
5. **DMARC** — если записи `TXT` с именем `_dmarc` ещё нет, добавить:
   Name `_dmarc`, Content `v=DMARC1; p=none`. Если есть — не трогать.
6. Вернуться в Postbox и дождаться статуса **Success** у DKIM. Обычно это
   минуты или несколько часов; если за сутки статус не сменился — проверить
   записи и нажать **Запустить проверку**.

Подробно: [создание адреса](https://yandex.cloud/ru/docs/postbox/operations/create-address),
[DNS-записи для Postbox](https://yandex.cloud/ru/docs/postbox/concepts/dns-records).

### 4. Функция

1. Каталог `dentalcruise` → **Cloud Functions** → **Создать функцию**.
   Имя: `dentalcruise-booking`.
2. Откроется **Редактор**. Среда выполнения — **Node.js 22** (`nodejs22`),
   галочку «Добавить файлы с примерами кода» снять.
3. Способ — **Редактор кода**. Создать файл `index.js` и вставить в него
   содержимое [`index.js`](index.js) из этой папки целиком. Больше файлов не нужно
   (`index.test.js` — тесты, в облако их не загружают).
4. Параметры:
   - **Точка входа**: `index.handler`
   - **Таймаут**: `10` секунд
   - **Память**: `128 МБ`
   - **Сервисный аккаунт**: `dentalcruise-booking`
   - **Переменные окружения**:

     | Ключ | Значение |
     |---|---|
     | `ALLOWED_ORIGINS` | `https://dentalcruise.ru,https://www.dentalcruise.ru,https://nikitadm1trievich.github.io` |
     | `MAIL_FROM` | `site@dentalcruise.ru` |
     | `MAIL_TO` | `info@dentalcruise.ru` |

   `MAIL_FROM` — адрес отправителя; ящик заводить не нужно, но домен должен быть
   тем, что подтверждён в Postbox. Секретов здесь нет, поэтому Lockbox не нужен.
5. **Сохранить изменения** — создастся версия функции.
6. На странице функции **не включать** «Публичная функция»: снаружи её
   вызывает только шлюз от имени сервисного аккаунта.

### 5. Ограничить масштабирование

Это часть защиты от спама (см. «Ограничение частоты» выше).

1. Открыть функцию. В блоке **История версий** навести курсор на тег `$latest`
   и во всплывающем окне нажать **Добавить**.
2. Заполнить: **zone_instances_limit** — `1`, **zone_requests_limit** — `10`,
   **provisioned_instances_count** — `0` (подготовленные экземпляры платные и
   не нужны).
3. **Сохранить**. Настройка применяется в течение пяти минут.

То же самое одной командой [yc CLI](https://yandex.cloud/ru/docs/cli/quickstart),
если он установлен ([инструкция](https://yandex.cloud/ru/docs/functions/operations/function/scaling-settings-add)):

```bash
yc serverless function set-scaling-policy \
  --id=<ID_функции> --tag='$latest' \
  --zone-instances-limit=1 --zone-requests-limit=10
```

### 6. API Gateway

1. Скопировать идентификаторы: у функции — на её странице «Обзор»
   (поле «Идентификатор»), у сервисного аккаунта — на его странице.
2. Каталог `dentalcruise` → **API Gateway** → **Создать API-шлюз**.
   Имя: `dentalcruise-booking`.
3. В поле **Спецификация** стереть пример и вставить содержимое
   [`openapi.yaml`](openapi.yaml), заменив `<ID_функции>` (три места) и
   `<ID_сервисного_аккаунта>` на скопированные значения.
4. Создать. На странице шлюза появится **Служебный домен** вида
   `https://d5dxxxxxxxxxxxxxxxxx.apigw.yandexcloud.net` — это адрес обработчика.

### 7. Проверить

Подставьте служебный домен шлюза вместо `<шлюз>`:

```bash
curl https://<шлюз>.apigw.yandexcloud.net/health
# {"ok":true}

curl -i -X OPTIONS https://<шлюз>.apigw.yandexcloud.net/booking \
  -H 'Origin: https://dentalcruise.ru' -H 'Access-Control-Request-Method: POST'
# HTTP 204 и строка access-control-allow-origin: https://dentalcruise.ru

curl -X POST https://<шлюз>.apigw.yandexcloud.net/booking \
  -H 'Content-Type: application/json' \
  -d '{"name":"Проверка","contact":"+79255777677","consent":"on"}'
# {"ok":true} — и письмо «Заявка с сайта: Проверка» в ящике info@dentalcruise.ru
```

Если пришло `{"ok":false,"error":"Не удалось передать заявку. Позвоните нам."}` —
причина в логах функции (функция → **Логи**): там будет строка «Postbox не
настроен…» или «Postbox отклонил письмо…» с кодом ошибки. Частые причины: домен
ещё не подтверждён (`MailFromDomainNotVerifiedException`), функции не назначен
сервисный аккаунт, адрес в Postbox создан в другом каталоге.

Первое письмо проверьте и в папке «Спам». Если оно там — отметьте «Не спам»
и добавьте `site@dentalcruise.ru` в контакты ящика.

### 8. Прописать адрес на сайте

Эндпоинт — это служебный домен шлюза плюс `/booking`. Положить его:

- локально — в `.env` в корне репозитория:
  `PUBLIC_BOOKING_ENDPOINT="https://<шлюз>.apigw.yandexcloud.net/booking"`
- на сборке — в переменную репозитория GitHub:
  **Settings → Secrets and variables → Actions → Variables → New variable**,
  имя `PUBLIC_BOOKING_ENDPOINT`. Затем перезапустить сборку
  (**Actions → «Сборка и публикация на GitHub Pages» → Run workflow**) или дождаться следующего пуша в `main`.

После этого отправить настоящую заявку с сайта и убедиться, что письмо пришло.

## Как обновить код функции

Поменяли `index.js` — открыть функцию → **Редактор**, заменить содержимое
файла и **Сохранить изменения**. Шлюз всегда вызывает последнюю версию
(`$latest`), его трогать не нужно.

## Разработка и тесты

Облако для тестов не нужно: отправка письма подменяется заглушкой.

```bash
cd booking
npm install      # только TypeScript для проверки типов, в облако не уходит
npm test         # node:test — валидация, телефон, CORS, лимит, ловушка, ответы
npm run check    # tsc проверяет типы из JSDoc
```

Чтобы проверить форму с дев-сервера Astro на живой функции, временно добавьте
`http://localhost:4321` в `ALLOWED_ORIGINS` и уберите после проверки — в боевом
списке localhost не нужен.

## Когда сайт переедет на домен клиники

`https://dentalcruise.ru` и `https://www.dentalcruise.ru` в `ALLOWED_ORIGINS`
уже есть. Когда тестовая сборка на GitHub Pages станет не нужна, уберите
`https://nikitadm1trievich.github.io` из списка (функция → Редактор →
переменные окружения → Сохранить изменения).
